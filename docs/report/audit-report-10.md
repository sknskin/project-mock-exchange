## 3. 상 (Critical) — 3건

### #1. 카피 트레이딩 스케일 비율 입력값 범위 미검증

- **심각도:** 상
- **영역:** 백엔드 보안 — 카피 트레이딩
- **파일:** `backend/services/portfolio/src/copy-trade/` (CopyTradeConfig 관련)
- **설명:** CopyTradeConfig의 `scaleRatio` 필드에 대한 서버 측 범위 검증이 부재합니다. 사용자가 극단적 비율(예: 100x, 0x, 음수)을 설정할 경우 카피 트레이딩 실행 시 비정상적 주문 금액이 발생할 수 있습니다. 프론트엔드 UI에서 제한하더라도 API 직접 호출로 우회 가능합니다.
- **권장 수정:** DTO에 `@Min(0.01) @Max(10)` 등 합리적 범위 제한 데코레이터 추가. `maxInvestmentPerTrade` 필드도 동일하게 `@Min(1)` 검증 필요

---

### #2. 카피 트레이딩 동시 실행 시 잔고 경합 조건

- **심각도:** 상
- **영역:** 데이터 무결성 — 카피 트레이딩
- **파일:** `backend/services/portfolio/` (CopyTradeExecution 관련)
- **설명:** 팔로우 중인 트레이더가 동시에 여러 거래를 체결하면, 카피 트레이딩이 병렬로 주문을 생성합니다. 이 때 잔고 확인과 차감 사이에 경합 조건(race condition)이 발생하여 가용 잔고를 초과하는 주문이 체결될 수 있습니다.
- **권장 수정:** CopyTradeExecution 생성 시 `$transaction` + `FOR UPDATE` 락을 사용하여 잔고의 원자적 확인/차감 보장. `maxInvestmentPerTrade`와 별도로 카피 트레이딩 전체 일일 한도 설정 권장

---

### #3. 팔로우 API 응답 형식 불일치 (수정 완료 검증)

- **심각도:** 상 → **수정 완료**
- **영역:** 백엔드/프론트엔드 연동
- **파일:** 팔로우 API 엔드포인트, 프론트엔드 팔로우 훅
- **설명:** `followingData.map is not a function` 에러가 발생했던 건입니다. API가 배열이 아닌 객체(`{ data: [...], total: N }`)를 반환하는데, 프론트엔드에서 응답을 직접 `.map()`으로 순회하여 TypeError가 발생했습니다.
- **수정 확인:** API 응답에서 `data` 프로퍼티를 추출하거나, 응답 형식이 배열인지 확인 후 처리하도록 수정 완료

- **코드 전반 주석 표준화:** `docs: 코드 전반 한/영 이중 주석 추가` 커밋으로 기존 코드까지 주석 정비

### 13.3 결론

10차 감사는 VirtuEx의 **소셜/커뮤니티 기능 확장**을 중심으로 진행되었습니다. 팔로우 시스템, 활동 피드, 카피 트레이딩, 커뮤니티 공개 설정, 실시간 알림 등 사용자 경험을 크게 확장하는 기능들이 구현되었으며, 전반적인 아키텍처 통합이 우수합니다.

핵심 조치 사항:

1. **카피 트레이딩 안전성** (상 2건): `scaleRatio`/`stopLossPercent` 입력값 범위 검증, 잔고 경합 조건 해결이 최우선입니다. 금융 로직의 특성상 엣지 케이스가 실질적 자산 오류로 이어질 수 있습니다.
2. **서버 측 검증 강화** (중 4건): 자기 팔로우 방지, 전략 작성 자격 재검증, 카피 트레이더 수 제한 등 프론트엔드 제한만으로 불충분한 항목의 백엔드 검증이 필요합니다.
3. **데이터베이스 최적화** (하 3건): 신규 테이블의 인덱스, 유니크 제약, 데이터 보존 정책을 조기에 설정하여 데이터 증가에 대비해야 합니다.

9차 감사 48건 전량 수정(100%)은 프로젝트의 높은 품질 의식을 보여주며, 종합 성숙도 점수는 3.8에서 **3.9로 소폭 상승**했습니다. 카피 트레이딩의 금융 안전성 이슈 해결 후 4.0 이상 달성이 가능할 것으로 평가됩니다.
