## A. 접근성 (a11y) — 3건

### [A11Y-M-01] ARIA 속성 — 전체 컴포넌트 대비 적용률 낮음 (Medium)

**현상:** 약 80개 이상의 컴포넌트 파일 중 20개만 `aria-label`, `aria-describedby`, `role` 등의 ARIA 속성을 포함. 대다수 인터랙티브 요소(버튼, 드롭다운, 모달)에 적절한 ARIA 라벨링 부재. 특히 가격 실시간 업데이트 영역에 `aria-live` 속성 없음
**위치:** `frontend/src/components/` 전반
**영향:** 스크린 리더 사용자가 UI 요소의 목적과 상태를 파악할 수 없음
**권장:** 모든 인터랙티브 컴포넌트에 `aria-label` 추가, 동적 콘텐츠(가격, 알림)에 `aria-live="polite"` 적용
**심각도:** Medium

### [A11Y-M-02] 이미지 — alt 속성 및 lazy loading 부재 (Medium)

**현상:** 프론트엔드 전체에서 `alt` 속성을 사용하는 파일이 2개뿐. `loading="lazy"`, `fetchPriority` 미사용. Next.js `Image` 컴포넌트 대신 raw `<img>` 태그 사용 케이스에서 eager 로딩 발생
**위치:** `frontend/src/` 전반, 특히 `dangerouslySetInnerHTML`로 렌더링되는 커뮤니티 콘텐츠
**권장:** Next.js `Image` 컴포넌트 활용, 사용자 콘텐츠의 `<img>`에 `loading="lazy"` 추가
**심각도:** Medium

### [A11Y-L-01] 커뮤니티/전략 게시글 — 상대 시간 미지원 (Low)

**현상:** 날짜가 ISO 문자열 또는 절대 타임스탬프로 표시. 소셜 커뮤니티에서 표준인 상대 시간("2시간 전", "어제") 미지원으로 시간 인지 불편
**위치:** 커뮤니티 페이지 관련 컴포넌트 전반
**권장:** `date-fns/formatDistanceToNow` 등을 활용하여 최근 게시글은 상대 시간, 오래된 게시글은 절대 날짜 표시
**심각도:** Low

## B. 반응형 디자인 — 2건

### [RD-M-01] OrderForm — 반응형 클래스 전무 (Medium)

**현상:** OrderForm 컴포넌트에 `sm:`, `md:`, `lg:` 등 반응형 브레이크포인트 클래스가 전혀 없음. 모바일 기기에서 폼이 화면 크기에 맞게 조정되지 않아 입력 필드와 버튼이 좁게 표시
**위치:** `frontend/src/components/trading/OrderForm.tsx`
**권장:** 모바일 기기용 패딩, 폰트 크기, 레이아웃 방향 반응형 클래스 추가
**심각도:** Medium

### [RD-M-02] 대시보드 — 단일 대형 컴포넌트로 유지보수 어려움 (Medium)

**현상:** 대시보드 페이지가 489줄의 단일 컴포넌트로 AI 분석 모달, 스포트라이트 검색, 탭 관리, WebSocket 배칭, 기간 필터링을 모두 포함. 모든 상태 변경 시 전체 컴포넌트 리렌더링 발생
**위치:** `frontend/src/app/(main)/dashboard/page.tsx`
**권장:** AI 분석 모달, 탭 바, 필터 컨트롤을 독립 컴포넌트로 분리하여 각각 독립적 상태 관리
**심각도:** Medium

## C. 로딩/에러 피드백 — 2건

### [UX-M-01] 백엔드 에러 메시지 — 한국어 전용 하드코딩 (Medium)

**현상:** 백엔드 인증 에러 메시지가 한국어로 하드코딩("비밀번호가 일치하지 않습니다", "이미 등록된 이메일입니다"). 프론트엔드에 i18n 시스템(`useTranslation`)이 있으나 백엔드 에러는 직접 표시. 영문 로케일 사용자에게 한국어 에러 메시지 노출
**위치:** `backend/services/user-auth/src/application/services/auth.service.ts:95-98, 127-128`
**권장:** 백엔드에서 에러 코드 반환, 프론트엔드에서 번역하여 표시. 또는 Accept-Language 헤더 기반 다국어 에러 메시지
**심각도:** Medium

### [UX-L-01] 관심종목 토글 — 옵티미스틱 업데이트 미적용 (Low)

**현상:** 관심종목 추가/제거 시 서버 응답까지 대기 후 UI 반영. 별 아이콘 토글에 체감 지연 발생
**위치:** `frontend/src/app/(main)/dashboard/page.tsx:114-124`
**권장:** `useAddWatchlist`, `useRemoveWatchlist` 뮤테이션에 TanStack Query `onMutate` 옵티미스틱 업데이트 적용
**심각도:** Low

## D. 폼/입력 UX — 3건

### [FRM-M-01] 로그인 페이지 — 비밀번호 표시/숨기기 토글 없음 (Medium)

**현상:** 비밀번호 입력 필드가 `type="password"` 고정. 사용자가 입력 내용을 확인할 수 없어 오타로 인한 로그인 실패 빈도 증가
**위치:** `frontend/src/app/(auth)/login/page.tsx:115-121`
**권장:** eye/eye-off 아이콘 버튼으로 `type` 토글 (password ↔ text) 기능 추가
**심각도:** Medium

### [FRM-M-02] 입출금 폼 — 최대 금액 검증 없음 (Medium)

**현상:** 입금 시 양수면 무제한 입력 가능. 극단적 금액(예: 999999999999) 입력 시 숫자 포맷 깨짐 또는 Decimal 오버플로우 가능. 모의 거래 플랫폼이지만 합리적 제한 필요
**위치:** `frontend/src/app/(main)/portfolio/page.tsx:75-101`
**권장:** 최대 입금 한도(예: $1M 또는 100억 원) 설정 + 초과 시 피드백 메시지
**심각도:** Medium

### [FRM-L-01] 계정 초기화 — 이중 확인 메커니즘 부재 (Low)

**현상:** `useResetAccount()`는 모든 보유 자산과 거래 내역을 삭제하는 파괴적 작업. 훅 자체에 이중 확인 메커니즘이 없어 호출자가 확인 다이얼로그를 구현하지 않으면 즉시 실행
**위치:** `frontend/src/hooks/usePortfolio.ts:213-229`
**권장:** 훅 내부 또는 호출부에 2단계 확인 플로우 내장 (텍스트 입력 "RESET" 확인 등)
**심각도:** Low

## E. 모달/포커스 관리 — 2건

### [MOD-M-01] 인라인 모달 — 포커스 트랩 미적용 (Medium)

**현상:** `useFocusTrap.ts` 훅이 존재하지만 대시보드 AI 분석 모달 등 인라인 모달에서 미사용. Tab 키로 모달 뒤 배경 요소에 포커스 이동 가능
**위치:** `frontend/src/app/(main)/dashboard/page.tsx:397-485`, 기타 인라인 모달
**권장:** 모든 `role="dialog"` 모달에 `useFocusTrap` 적용
**심각도:** Medium

### [MOD-L-01] AI 분석 모달 — Escape 키 닫기 미지원 (Low)

**현상:** AI 분석 모달에 `role="dialog"`, `aria-modal="true"` 설정은 있으나 Escape 키 핸들러 없음. 키보드 사용자가 닫기 버튼 또는 배경 클릭으로만 닫을 수 있음
**위치:** `frontend/src/app/(main)/dashboard/page.tsx:397-485`
**권장:** `onKeyDown` 핸들러에서 Escape 키 누름 시 모달 닫기 추가
**심각도:** Low

## F. 테마/다크모드 — 1건

### [THM-L-01] 다크 모드 전용 — 라이트 모드 미구현 (Low)

**현상:** CSS `@theme` 블록에 다크 모드 색상만 정의(`bg-primary: #17171C`). Header에 테마 전환 버튼이 있으나 라이트 모드 CSS 변수가 정의되지 않아 토글해도 변화 없음
**위치:** `frontend/src/app/globals.css:20-40`
**권장:** 라이트 모드 CSS 변수 정의 + Tailwind `dark:` 또는 CSS 커스텀 프로퍼티를 통한 테마 전환 구현
**심각도:** Low

## G. 국제화/에러 메시지 — 1건

### [I18N-M-01] 백엔드 에러 메시지 — 프론트엔드 i18n 미연동 (Medium)

**현상:** 백엔드에서 한국어 에러 문자열을 직접 반환하고 프론트엔드가 이를 그대로 표시. 프론트엔드의 `useTranslation()` 시스템과 별도로 동작하여 언어 설정과 무관하게 한국어 에러 표시
**위치:** 백엔드 서비스 전반의 `throw new BadRequestException('한국어 메시지')`
**권장:** 에러 코드 체계 도입 (예: `AUTH_INVALID_PASSWORD`) → 프론트엔드에서 코드를 번역 키로 매핑
**심각도:** Medium

## H. 빈 상태/안내 — 1건

### [EMP-L-01] 포트폴리오 분석 탭 — 빈 상태 안내 부재 (Low)

**현상:** 보유 자산이 없는 상태에서 "분석" 탭 클릭 시 `PortfolioAnalytics` 컴포넌트가 빈 차트 영역을 표시. 사용자에게 "자산을 추가하면 분석이 시작됩니다" 등의 안내 없음
**위치:** `frontend/src/app/(main)/portfolio/page.tsx:334`
**권장:** `portfolio.holdings.length === 0` 시 의미 있는 빈 상태 UI 표시
**심각도:** Low

## 종합 의견

1차 UX 개선 감사에서는 총 15건의 이슈가 발견되었습니다. Critical/High 이슈는 없으나, Medium 9건은 사용자 경험 품질에 직접적인 영향을 미치는 항목들입니다.

접근성(a11y) 측면에서 ARIA 속성 적용률이 전체 컴포넌트의 약 25%에 불과하여 스크린 리더 사용자 지원이 부족합니다. OrderForm의 반응형 미지원은 모바일 사용자 경험을 저해하며, 백엔드 에러 메시지의 한국어 하드코딩은 글로벌 사용자 지원에 장애가 됩니다.

포커스 트랩 훅이 이미 구현되어 있으므로 모든 모달에 일괄 적용하면 키보드 접근성을 크게 개선할 수 있습니다. 비밀번호 표시 토글, 입출금 최대 금액 검증, 상대 시간 표시 등은 비교적 적은 노력으로 높은 UX 개선 효과를 기대할 수 있습니다.
