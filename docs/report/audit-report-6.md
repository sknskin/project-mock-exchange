**상세 설명:**

- **#1:** user-auth 장애 시 JWT 서명만으로 인증 통과 — 비활성화/잠긴 계정도 접근 가능. 503 반환 필요
- **#2:** `'virtuex-salt'` 고정 솔트 사용 — 레코드별 랜덤 솔트로 변경 필요
- **#3:** `Math.random()` 사용 — `crypto.randomInt(100000, 999999)`로 변경 필요
- **#4:** 로그인 API에 별도 레이트 리밋 없음 (글로벌 100req/min만) — 5req/min 개별 제한 필요
- **#5:** 주문 생성에 개별 쓰로틀 없음 — 매칭 엔진 스팸 공격 가능. 100req/min 제한 권장
- **#6:** 60초당 5회 허용 — 봇 계정 생성 가능. CAPTCHA 또는 일일 제한 추가 필요
- **#7:** 익명 클라이언트 최대 5채널 구독 가능 — IP당 연결 수 제한 필요
- **#8:** Redis 캐시 TTL 60초 — 비활성화 사용자 최대 1분 접근 가능. 15-30초 축소 권장
- **#9:** Guard + 메서드 내 수동 검사 혼용 — `@Roles(ADMIN)` 데코레이터 통일 필요
- **#10:** 의도된 설계 — 보안적으로 올바르나 안내 메시지 개선 권장
- **#11:** 모든 서비스 동일 `INTERNAL_SERVICE_SECRET` 사용 — 서비스별 분리 권장 (장기)

### 10.4 즉시 수정 권장 사항 (상 위험도 8건)

1. **JWT 폴백 인증 우회** — user-auth 서비스 장애 시 503 반환으로 변경
2. **주민번호 솔트 하드코딩** — 레코드별 랜덤 솔트 생성
3. **SMS 코드 비암호학적 난수** — `crypto.randomInt()` 사용
4. **주문 가격/수량 DoS** — `@MaxLength(50)` 추가
5. **주문 취소 자금 해제 레이스 컨디션** — 트랜잭션 래핑
6. **매도 주문 보유량 이중 지출** — 보유량 예약 메커니즘 구현
7. **인메모리 오더북 초기화 경쟁** — 원자적 초기화 또는 Redis 전환
8. **서비스 URL 하드코딩 폴백** — `getOrThrow()` 사용

### 10.5 프로젝트 강점

- **마이크로서비스 아키텍처:** 8개 서비스 분리 + CQRS/이벤트 소싱 패턴 적용
- **인증 체계:** JWT + 2FA(TOTP) + 계정 잠금 + timing-safe 비교
- **인프라 구성:** Docker Compose + Prometheus + Grafana + Jaeger 모니터링
- **프론트엔드 설계:** Zustand + React Query 조합, WebSocket 실시간 가격
- **코드 품질:** TypeScript strict 모드, ESLint, Prettier, Husky 적용
- **i18n 지원:** 한국어/영어 다국어 구현 완료
- **DB 설계:** UUID 기반 ID, 적절한 인덱싱, Cascade 삭제
